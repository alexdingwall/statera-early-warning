# Decisions

- Branch renamed from master to main; PLAN.md copied into the repo root.
- Backend is a flat, non-packaged uv app (no build backend): `uv init --app` created a src layout, which was removed so `app.*` imports work from `backend/`.
- pytest `pythonpath = ["."]` in backend/pyproject.toml so tests import `app`.
- Frontend: added dev dependency `@types/node` (needed for the `@/` alias in vite.config.ts). shadcn init added its own dependencies (radix-ui, class-variance-authority, tailwind-merge, tw-animate-css, @fontsource-variable/geist); the Geist font will be replaced by Montserrat and Inter in Phase 6.
- TypeScript `baseUrl` omitted (deprecated); `paths` alone resolves `@/*`.
- Board claim splitting keeps fragments of 2+ words (plan says under 3 words are dropped), because gold expects the 2-word claim "Construction complete." and only the 1-word "Weather" should drop.
- Gold-mode programme snapshots are read deterministically from each document's programme block with regexes (gold.yaml holds no programme values).
- Embeddings (cross-project matching) are used in gold mode too, read from the committed cache, so a gold rebuild on a machine with an empty cache needs Ollama for embeddings only.
- Identity: one mention per issue per document is enforced first-come in document order, not by highest score as the plan words it.
- Duplicate alert ids (two triggers staging the same stage on one issue) get a numeric suffix.
- Gold build also shows two extra cross-project matches beyond the three expected (DRU-COND9 to NET-PLANNING, ASH-SNAG to NET-FIRMWARE), neither on the no-match list.
- Phase 2 code was committed together with Phase 3.
- Demo bundle is the LLM build: it passes the plan's gates (first ASH-DNO alert 5 May 2025, "Low risk" claim contradicted with no fallback, 2 of 3 expected matches found). Known weaknesses are shown on the Evaluation page: over-extraction (precision 68%), category accuracy 46%, trigger dates 25%, DRU-ACCESS to ASH-CRANE not matched, and the two Drumgarve matches are medium rather than high confidence.
- Frontend: shadcn generated `cn` imports from an unrelated npm package named `cn`; replaced with a local clsx-based `cn` in src/lib/utils.ts and removed that package and the Geist font package. Class conflicts are not merged (no tailwind-merge), so overrides rely on class order.
- Dashboard: Taste inspector (--app) left only defended findings: the plan-mandated uppercase "Project delivery" label, blank space inside stretched cards at 1440×900 (fixed-density views are not padded), and no h1 at 768/390px (the plan asks for a simple "Best viewed on a larger screen." message, not a mobile layout).
- Identical staged alerts (same issue, rule, stage and day, from triggers in different documents) are merged in rules.compute.
- Deep links for demos and screenshots: `#/path?asof=2025-06-30&gt=1`.
- Added data/lessons.yaml (hand-entered from the Netherwood lessons workshop: actions, owners, status as written, and where each applies) so the dashboard can show lessons learned and where they recur. Not extracted by the model.
- Programme snapshots are read from the documents by regex in LLM mode too (the model invented float values such as 0 days when none was stated); the model is only a fallback. A materialised status on a retrospective document type (commissioning summary, lessons learned) is corrected to occurred in code.
- LLM-mode programme snapshots come only from the regex parser; the model never supplies them (it invented float and dates for documents without a programme block).
- Dashboard reframed around an action queue: one decision per issue with an active red or amber alert, ranked preventable first (nearest stated deadline), then problems already affecting the programme. Recommendations, "why now", stakes and "last time" are templated from data in frontend/src/lib/actions.ts (no model text). Escalate / Acknowledge / Snooze are recorded in browser storage only; nothing is sent anywhere.
- The page scrolls as a whole (not inside the issue card); the issue list stays pinned beside the detail and the top and replay bars stay fixed. Text wraps instead of truncating.
- Board-claim prompt reworked into an ordered decision procedure (was 5 of 7 claims contradicted). After removing internal ids from the evidence pack it returns 3 of 7 contradicted (gold expects 2); the two that matter are among them, no fallbacks. Not tuned further to avoid fitting the answer.
- Watch notes (backend/app/watch.py): shown from the first incident of a counterparty and category on another project until this project raises the same kind of issue with that counterparty. Which counterparties a project uses is treated as known from the start, as the mapping is hand-entered. No model calls.
- Chase counts show the highest figure any report states ("At least N"), because later reports often say only "chased again". Board-check evidence names issues by title, not internal id.
- Adding a report: POST /api/documents saves it to data/uploads/ (git-ignored), reads it with the local model, rebuilds the bundle, and returns it; DELETE returns to the sample. Added reports are excluded from the evaluation scores (no human labels). The synthetic sample report (frontend/public/samples/) is invented, marked as such in its first line, and kept consistent with the real wk27 and DNO summary. No new dependency (JSON body, not multipart).
- Queue tiers: Act now (already affecting the programme, or a stated deadline within 30 days), Prepare, Keep an eye on, Past incidents. The 30-day threshold is an assumption. Issues raised only in retrospective documents (commissioning summary, lessons workshop) are past incidents. Related issues from the same report and counterparty fold into one item.
- One issue view is shared by the Portfolio and project pages: decision block, then a History list (what each report said, warnings, the deadline ahead). The flag timeline and the Alerts, Triggers and Evidence tabs were removed as duplicates.
- A saved decision (escalate, acknowledge, snooze) stands until a later report mentions the issue, a new warning fires, or a snoozed deadline is within 7 days; then it returns to the queue with the reason. A decision only counts from the date it was made, so the replay stays correct. Stored in browser localStorage only.
- "New since the previous report" is relative to the replay (the previous report date), not to a real last visit. In a live version it would be relative to the user's last visit.
- A revised deadline does not replace the old one: in the labelled data two deadlines on one issue can both be real, so replacing would drop a real warning. It needs the model to flag a revision.
- The app opens on the first report (31 Dec 2024) and keeps the date across a refresh in the same tab (sessionStorage); a date in the link wins.
- Hosted copy: public, read-only, noindex, on Vercel Hobby (the user chose this because the documents are synthetic). It never contacts localhost. Adding a report works only with the backend and Ollama running locally.
